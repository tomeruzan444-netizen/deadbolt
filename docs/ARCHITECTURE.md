# Architecture: Deadbolt Fixers

Phase 1 plan. This covers the stack, file layout, data model, components, schema strategy, design system and QA tooling. Content rules live in `CONTENT-GUIDE.md`; keyword ownership in `KEYWORD-MAP.md`.

## Stack

| Concern | Choice | Why |
|---|---|---|
| Framework | Astro 5, `output: 'static'`, TypeScript strict | Zero JS by default, content collections, static HTML for crawlers |
| Content | MDX content collections with Zod-validated frontmatter | New page = new file; build fails on missing SEO fields |
| Styling | Hand-written CSS with custom properties (tokens), one global sheet + scoped component styles | Smallest output, full design control, no framework purge step needed |
| Fonts | `@fontsource` packages, self-hosted WOFF2, Latin subset, `font-display: swap`, preload 2 files | No runtime Google Fonts requests |
| JS | Inline `<script>` islands only: mobile menu, header compact-on-scroll, contact form validation | Target under 3 KB JS per page |
| FAQ | Native `<details>/<summary>` | No JS |
| Sitemap | `@astrojs/sitemap` | Automatic |
| robots.txt, llms.txt | Astro endpoints (`src/pages/robots.txt.ts`, `src/pages/llms.txt.ts`) generated from config + collections | Always in sync with pages |
| Hosting | Vercel, static | `vercel.json` with trailing slash + cache headers |
| QA | Node scripts in `scripts/` run against `dist/` HTML (`node-html-parser`), plus Lighthouse CLI | Enforces the content guide automatically |

URL config: `trailingSlash: 'always'`, `build.format: 'directory'`, `site` read from `src/config/site.ts`.

## Content model

Shared frontmatter for `services`, `guides`, `pages`, `areas`:

| Field | Type | Notes |
|---|---|---|
| `title` | string | Short name for nav, cards, breadcrumbs |
| `h1` | string | Validated at build: must contain `keyword` (case-insensitive) |
| `metaTitle` | string | 50-60 chars warned in QA |
| `metaDescription` | string | 140-160 chars warned in QA |
| `keyword` | string | Must be unique across the site (build fails on duplicates) |
| `secondaryKeywords` | string[] | |
| `intent` | enum | transactional / commercial / informational / navigational |
| `intro` | string | Answer-first paragraph |
| `keyFacts` | string[]? | |
| `cardBlurb` | string | One-sentence unique description for hubs/cards |
| `toc` | boolean | |
| `published`, `updated` | date | `updated` shown on services and guides |
| `angle` | string | Not rendered; uniqueness tracking |
| `faqs` | {q, a}[] | 10-15 enforced by Zod (except legal) |
| `sources` | {title, publisher, url, supports}[] | |
| `order` | number | Menu/hub ordering (services) |
| `icon` | string | Service icon key |

Legal entries: `title`, `metaTitle`, `metaDescription`, `updated`, `reviewed` only.

## Contact config behavior

`src/config/site.ts` exports one object. `phone`, `email`, `address` start as empty strings/`null` with `TODO` comments. Helpers `hasPhone()`, `hasEmail()`, `hasAddress()` gate every render:

- Header "Call Now": phone only.
- Mobile CTA bar: shown if phone or email exists; each button individually gated.
- Footer / contact page / sidebar card: each line gated; the whole block is omitted if all are empty (the contact page then shows the form only).
- Schema: `telephone`, `email`, `address` keys omitted when empty (never `""`).
- Form: `formEndpoint` in config. If empty, the form validates client-side and shows an accessible message that online booking is being set up (no fake success).

## Structured data plan

Emitted as one `@graph` per page, built in `src/lib/schema.ts` with stable `@id`s:

| Entity | Pages | `@id` |
|---|---|---|
| `Organization` | all | `{base}/#organization` |
| `WebSite` | all | `{base}/#website` (publisher -> organization) |
| `Locksmith` | all | `{base}/#locksmith` (`areaServed: { @type: Country, name: United States }`, parentOrganization -> organization; telephone/address only when set) |
| `Service` | service pages, service-area pages | `{url}#service` (provider -> locksmith, `serviceType` = title, `areaServed` US or the city/state) |
| `Article` | guides | `{url}#article` (author + publisher -> organization, datePublished, dateModified) |
| `WebPage` | all | `{url}#webpage` (breadcrumb, isPartOf website) |
| `BreadcrumbList` | all except home | `{url}#breadcrumb` |
| `FAQPage` | every page with FAQs | `{url}#faq` |

No `AggregateRating`, `Review`, `foundingDate` or `numberOfEmployees` until real data exists.

## Breadcrumb logic

`src/lib/urls.ts` maps each entry to its logical parent, independent of URL depth:

- Service: Home > Services > {title} (URL `/{slug}/`)
- Guide: Home > Deadbolt Guides > {title}
- Area: Home > Service Areas > {State} > {City}
- Other: Home > {title}

## Design system ("precision hardware")

Tokens (final values tuned for WCAG AA in Phase 4):

| Token | Value (starting point) | Use |
|---|---|---|
| `--ink` | `#14171C` | Dark sections, body text on paper |
| `--graphite` | `#22272F` | Header, cards on dark |
| `--steel-700` / `--steel-400` / `--steel-200` | `#4A525E` / `#8C949F` / `#D5D9DE` | Lines, borders, secondary text |
| `--paper` | `#F5F2EB` | Reading surfaces |
| `--brass` | `#C9A04E` | Accent on dark backgrounds, illustration lines |
| `--brass-ink` | `#7A5A1C` | Brass-tone text/links on paper (AA) |
| `--cta` | `#E2B04A` on ink text | Primary call-to-action buttons |

Typography (all OFL, self-hosted):
- Display: **Archivo** (variable, using the expanded width axis for headings: an engineered, machined feel).
- Text: **Assistant** (variable, 400-700, Latin subset) for all body copy; line-height 1.7, measure ~68ch.
- Spec labels: **IBM Plex Mono** 500 (small caps-style labels, step numbers, dimensions). Not preloaded.
- Preload: Archivo (heading weight) and Assistant only.

Signature elements: blueprint grid texture (CSS gradients, no image), dimension lines with arrowheads as section dividers, numbered circular callouts, "spec sheet" key-facts boxes with mono labels, exploded deadbolt hero SVG with annotated 1" throw.

Motion: hover/focus transitions under 200 ms, FAQ chevron rotation, header shrink; all disabled under `prefers-reduced-motion: reduce`.

| Metric | Budget |

| HTML (service page, gzip) | under 35 KB |

## QA tooling (Phase 6)

`npm run qa` (after `npm run build`) parses every HTML file in `dist/` and reports:

- One H1; H1 contains exact keyword
- Exact keyword count in body prose ≥ 5 (scope per `CONTENT-GUIDE.md` §4), in first paragraph, in an H2
- FAQ count 10-15; FAQ duplicates (exact + near-duplicate via token similarity) across pages; writes `docs/FAQ-REGISTER.md`
- Body contextual internal links ≤ 5 (grids, forms and CTA boxes excluded), no target linked twice, every anchor shares a topic word with its target page; broken internal links (every href resolves to a file in `dist/`)
- Title 50-60, meta description 140-160
- Heading levels never skip
- Banned words/patterns, em/en dashes, site-wide "peace of mind" ≤ 1
- Duplicate paragraphs across pages (normalized hash + similarity)
- JSON-LD parses, required properties present, no empty contact fields
- sitemap.xml lists every page; robots.txt allows the required bots; llms.txt links every key page
- Click depth from home ≤ 3

`npm run lighthouse` runs mobile Lighthouse on home, one service page and one guide against `astro preview`, failing under 95 in any category.

## Build order (Phases 3-5)

1. Scaffold Astro, config, tokens, base layout, header/footer/mobile bar
2. Collections + schemas + `urls.ts` + `schema.ts` + routes rendering placeholder-free stubs
3. Sidebar, breadcrumbs, TOC, FAQ, CTA, contact form
4. SVG graphics and visual identity pass
5. Content, one page at a time (home, hubs, 12 services, 5 guides, about, contact, legal, 404)
6. QA scripts, fixes, Lighthouse
7. README hand-off
